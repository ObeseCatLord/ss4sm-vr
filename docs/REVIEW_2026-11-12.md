## Performance

- The log is flushed to disk at most every 2 s (it was flushed per line). Pad button changes are logged only with
  `input_log=1`.
- GPU timing keeps its submit buffers: no heap allocation per submit.
- The per-pass open render pass set became a per-thread list (no lock, no allocation).
- Device functions are resolved once per call site (present resolved about 15 by name each frame).
- Weapon file names are cached per params (each lookup cost about 6 `VirtualQuery` calls).
- The foveation bind hook skips its lock while no pipeline has dynamic shading rate.
- Menu saves are debounced while a slider is dragged.
- The mirror no longer blits when the runtime says not to render.

## Suggestions taken

- **Guards by default** for a modded desktop player (`mp_guards`, 1): a VR peer can no longer crash an unguarded
  modded game.
- **Pause on focus loss** (`pause_on_focus_loss`, 1): when the session leaves FOCUSED (dashboard), the game's menu
  opens through the Menu spot's native action.
- **Shipped logic under test:** `core/grip_swing.hpp` (foregrip reach, head-relative swing gate) is used by the local and
  authority grip paths and the blade sweep, with `tests/grip_swing_checks.cpp`.
- **Arms seqlock:** one writer at a time (the placement hook tries the lock).
- **Attach under the loader lock:** kept, as verified on Wine (the hooks must precede the engine's init). The comment
  now says what attach really does.
- **Not taken:** staying flat when an unmodded server never acknowledges. The client only learns the server's answer
  after joining, by which time its VR state has replicated; the client logs the missing acknowledgement.
